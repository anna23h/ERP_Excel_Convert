# 发票比价核对

用户给一组发票号或 SO 号，要确认「售价和采购价是不是都对」。
**`procure/price_check.py` 已经按用户定的口径做完全部计算，本流程不改代码、不临场写脚本。**

## 第一步：直接跑，不必先问

```bash
python3 -m procure.price_check INV/2026/11/0069 INV/2026/11/0070
python3 -m procure.price_check S04084 S04094          # SO 号也行，可与发票号混用
```

- 给 SO 号 → 取它下面**已过账**的客户发票；草稿/退款单不计入，脚本会打印出来。
- 用户贴的是「SO + 发票号」成对的，直接传发票号即可（更准，不会把同 SO 下的其他发票带进来）。
- 用户在发票号后面括号里写的数字（如 `(10194414)`）是发票的 ref / 客户订单号，**不是参数**，别传。
- 产出默认落 `output/YYYYMMDD/比价-<参数>-YYYYMMDD.xlsx`（每张发票一个 sheet），同名自动加序号。
  凭据走 `config.py` 的 `ODOO` 或环境变量 `ODOO_URL/DB/USER/API_KEY`。

退出码 1（`✗ …`）就停下，把原因原样交给用户，**不要绕过护栏自己算**。最常见的是
「产品行净额合计 ≠ 发票不含税金额」——说明有不带产品的金额行（运费、手工行），比出来的合计不可信。

## 第二步：交表

1. 把脚本 stdout 里的 **Markdown 表原样贴出来**（每张发票一张表 + 合计行），不改列、不改顺序。
2. 给 xlsx 路径。
3. 只就带 ⚠ 的行说明，没有 ⚠ 就说「都对得上」。

## 固定格式（2026-11-06 用户定，不许改）

- **两边一律比去税后的净价。**本库销售税（19% / 7% Umsatzsteuer）是含税价
  `price_include=True`，`price_unit` 是**含税**；采购税（Vorsteuer）不含税。
  脚本已经按 `price_unit × (1 − 折扣) ÷ (1 + 含税税率)` 折净，**不要再拿 Odoo 界面上的含税单价去比**。
- **第一列 PZN，第二列品名。**之后依次是 税率 / 数量 / SO 净价 / 开票净价 / 采购价（PO）/
  单件毛利 / 毛利率 / 采购单号 / 采购日期 / 备注。
- 采购价 = **发票日当天或之前**最近一张已确认的 PO（剔除 Alibaba / VO Test Order）。

## ⚠ 怎么读

| 备注 | 意思 | 怎么跟用户说 |
|---|---|---|
| `SO 税率 X ≠ 开票税率 Y` | SO 行和发票行挂的税不一样 | **先看净价是不是一样**。一样就是税码问题、不是改价（含税单价会差约 10%，净价一分不差） |
| `开票价 ≠ SO 价（±n%）` | 去税净价真的不同（容差 1 分） | 报出差额，问用户是故意改价还是开错了 |
| `毛利 ≤ 0` | 开票净价不高于最近采购价 | 报出来 |
| `发票日前无采购记录` | 找不到可比的 PO，成本不计入合计 | 报出来，需人工另查 |

## 禁止项（这些都是 2026-11-06 踩过的）

- **不要直接比两个 `price_unit`。**第一版就是这么做的，把毛利从 6% 算成了 21%，被用户纠正。
- **不要只看含税价就下结论说「改价了」。**同一天 S04094 有 6 行含税价比 SO 低 10%，
  一度报成「开票少收 €937」，实际是 SO 行挂了 19%、发票挂 7%，**净价完全一致**。
- 不要自己另写 scratchpad 脚本重算——口径以脚本为准；脚本不对就立 issue 改脚本。
- 不要替用户判断「该按哪个价」，只把差异标出来。
