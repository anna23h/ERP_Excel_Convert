**拷到另一台 Mac**：复制 `vo_orders/`、`common/`、`requirements.txt` 和对应 `.command`（**不要拷 `.venv`、`raw_data/`**）。

**依赖按受众分三份**（2026-08-15）：`requirements.txt` 只有 `pandas`+`openpyxl`，是**启动器给同事装的最小集**（七条流水线依赖完全相同）；`requirements-dev.txt` = 最小集 + `pyinstaller`（打 exe 用）；`requirements-labels.txt` = `segno`/`reportlab`/`Pillow`（储位标签 `make_labels.py` 专用，按需单独装）。**别往 `requirements.txt` 加只有开发才用的包**——启动器会替同事装，装不上就是白挡人。

# 一、VO 拉单（VOTool 阶段一 / 阶段二）

```
导出当日 ERP + 天猫全量
        │
        ▼
[阶段一] vo_orders/build_excel.py ──► 拣货表+面单.xlsx ──► 打印给仓库
        │                                         │
        │                              仓库捡货、纸面标无货
        │                                         ▼
        │           办公室在「无货勾选」页把无货行填 1 另存；或用扫码回流出「有货清单」
        ▼
[阶段二] vo_orders/stage2.py（吃返回文件）──► B / C / D / E / 取消出库单
```

## 阶段一：生成「拣货表 + 面单」

```bash
python3 vo_orders/build_excel.py <erp[,erp2,...]> <完整天猫导出> [out.xlsx]
```

示例（多份 ERP 用**逗号**连接，不是空格）：

```bash
python3 vo_orders/build_excel.py raw_data/erpVO.xlsx,raw_data/erpGW.xlsx raw_data/天猫全量.xlsx
```

- **第二个参数是「完整天猫导出」**（全量、可跨多日，唯一天猫输入）。发货范围由程序二段式自动算出：`履约状态∈{新订单,商家已接单} ∧ 面单申请状态=已完成`，无需再单独导「面单已完成名单」。
- ERP 导出 **xlsx 或 csv 都可**，输出一致。
- 产出全部存到 `output/`，按店 `VO`/`GW` 各一份。

| 产出 | 内容 / 用途 | 何时跳过 |
|---|---|---|
| `YYYY年MM月DD日{店}{n}单 拣货表+面单.xlsx` | 三 sheet：`拣货表` / `面单`（打印给仓库）/ `无货勾选`（填 1 标无货） | — |
| `YYYY年MM月DD日{店}{n}单 扫码清单.csv` | 订单级白名单，与拣货表+面单同源同批 → 载入扫码 HTML（选用，见第七节） | — |
| `新订单获单清单{店}.xlsx` | `履约单状态=新订单` ∩ ERP 的系统履约单号 → 天猫后台批量获单 | 未传完整天猫导出 |
| `回传ERP销售上传表{店}.xlsx` | 取消 / 无运单 / 已补运单三类 Terms 写回**一张** → 上传 ERP | 无此三类订单 |
| `取消订单清单.xlsx` | 取消单种子表（**不分店**）。回传天猫后把后到的取消单手工补录进去，喂给阶段二生成取消出库单 | 当批无取消单 |
| `{店}补货预判清单.xlsx` | 今日需求 / 在手 / 缺口 + FS + Safety Stock + 采购画像 | **未传采购单导出**；或 ERP 导出没勾 `FS`/`Safety Stock`/`Supply Remark` 三列 |

> ⚠ **补货预判清单只有 GUI 有入口**：CLI 的第三个参数是输出路径，没有传采购单导出的位置（见 `build_excel.main()`）。要这张表就用 VOTool 阶段一的「采购单导出」（选填）栏。
> 它读的 `Safety Stock` 正是 `sales_insight` 回写进 ERP 的那个字段——两条流水线在这里接上。

- 打印格式已设：拣货表纵向压一页宽、面单横向、页脚「第 N 页，共 M 页」。

## 阶段二：仓库返回后

```bash
python3 vo_orders/stage2.py --mmdd <MMDD> --erp <ERP导出...> \
    [--shipped <有货清单...> | --nogoods <无货勾选返回...>] \
    [--tmall-full <完整天猫导出>] [--picking <出库原始数据...>] \
    [--cancel-list <取消订单清单...>] [--shipdate YYYYMMDD]
```

完整示例：

```bash
python3 vo_orders/stage2.py --mmdd 0611 \
    --erp raw_data/erpVO.xlsx raw_data/erpGW.xlsx \
    --shipped ~/Downloads/有货清单VO198单.csv \
    --picking raw_data/出库原始数据.xlsx \
    --cancel-list output/取消订单清单.xlsx
```

### 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `--erp` | ✅ | ERP 导出，**空格分隔可多份**（VO/GW 各一份）。货代合并模式除外 |
| `--mmdd` | 否 | 标签日期，默认今天，用于账单 D 的 `账单MMDD` 标签 |
| `--shipped` | 否 | **有货入口**（推荐）：真实发货订单清单，含履约单号/Order Reference 即可，可多份。吃 `.xlsx` 也吃 `.csv`（扫码回流导出的 zip 解压后，各店 `有货清单{店}{n}单.csv` 投这里） |
| `--nogoods` | 否 | **无货入口**：仓库返回的无货勾选文件，可多份。用它时需配 `--tmall-full` 算拣货候选 |
| `--tmall-full` | 否 | 完整天猫导出。无货入口算候选时必需；有货入口不需要 |
| `--picking` | 否 | 出库原始数据（stock picking 全量导出），可多份 → 出 `出库单.xlsx`（合并一张不分店）|
| `--cancel-list` | 否 | 取消订单清单（阶段一产出 + 人工补录后到的），**配 `--picking`** → 多出一张 `取消出库单.xlsx` |
| `--shipdate` | 否 | 发货日期 YYYYMMDD，默认今天 |
| `--billing` | 否 | **回落用**。ERP 导出含 `External ID` 列时账单直接由它生成；没有 ID 列才用这个喂账单模板导出 |
| `--forwarder` | 否 | 货代合并模式，见下（给了它其余参数忽略） |
| `--outdir` | 否 | 输出目录，默认 `output` |

`--shipped` 和 `--nogoods` 填其一即可（都填以有货为准）。

### 产出

| 产出 | 内容 |
|---|---|
| `系统履约单号.xlsx` (B) | 实际发货履约单号 → 上传天猫确认发货 |
| `发货表.xlsx` (C) | Order Reference + Tracking，GW / VO 分 sheet |
| `账单上传.xlsx` (D) | External ID + `账单MMDD` 标签 → ERP 开账单。**前提：ERP 导出含 `External ID` 列**，否则需 `--billing` |
| `出库单.xlsx` (E) | stock picking 过滤 + 统一发货日期，**合并一张不分店**（后缀 VO / GW / VO+GW 反映实际覆盖到的店）→ ERP 标记出库。需 `--picking` |
| `取消出库单.xlsx` | 取消订单的 picking，`Tracking Reference` 统一写 `订单取消`、不写 Carrier/ID、**合并一张不分店** → ERP 按此标记批量取消。需 `--picking` + `--cancel-list` |

各张独立，缺哪份输入就跳过哪张，不影响其他。

> **仅取消模式**：只带 `--cancel-list` + `--picking`（不给有货/无货清单）也能单独跑出取消出库单，便于收尾补跑；`--erp` 仍需带（作「别漏 ERP」护栏）。GUI 同理，「取消订单清单」为选填。

> ⚠ **`缺货记录.xlsx` 已从阶段二移除**，现在不产出了。未来单独成一个阶段（无货清单 × 库存 ERP 筛查），`build_shortage()` / `read_marked()` 作休眠代码保留（`stage2.py:356` 起）。

## 货代合并（跨店，收尾用）

```bash
python3 vo_orders/stage2.py --forwarder <发货表1> <发货表2> ... [--shipdate YYYYMMDD]
```

把当天各店、各次生成的「发货表」都传进来，去重合并。**产出两份**：

| 产出 | 内容 |
|---|---|
| `IHTCTGMBH+IH{YYYYMMDD}+{单数}.xlsx` | 给货代核对的合并清单（唯一跨店产出） |
| `YYYY年MM月DD日{n}单 天猫回执.xlsx` | 所有发货 Order Reference 后 15 位，各渠道合并去重 → 上传天猫做回执 |

运单冲突（同一 Order Reference 两个不同运单号）会在日志里报出，保留先出现的。

# 二、箱单（B2B 出口）

GUI：VOTool「箱单」标签页。CLI：

```bash
python3 packing_list/packing_list.py <sale.order.xlsx> [-o 输出目录] [--spare 2]
```

- 输入是 ERP 导出的 `sale.order` **行明细**。要几张 SO 合并成一张箱单，就在 ERP 里一次性导到同一份文件里，脚本按 `Order Reference` 自动分单。
- `--spare N`：每个 SKU 底下预留几行空行给仓库拆批次号/保质期（默认 2）。
- 产出照抄成品箱单排版：品名/SKU/条码/HS/原产国由脚本填；托盘号/批次号/箱号/箱规/箱数/保质期/毛重/尺寸/体积重留空给仓库手填；`Quantity total` 是公式 `=箱规×箱数`。
- 同名输出自动加序号，不覆盖。

# 四、销售分析 + 安全库存回写

📖 详见 [../sales_insight/README.md](../sales_insight/README.md)（含产品主数据导出该勾哪些列的对照表）。

GUI：`ERP回写-Mac.command` →「销售分析 · 安全库存」页。CLI：

```bash
python3 sales_insight/sales_insight.py <销售数据.xlsx> \
    --products <product.product.xlsx> \
    [--safety <运营的安全库存表.xlsx>] [--weeks N] [--cover-weeks 2] \
    [--test-sku <SKU>] [-o 输出目录]
```

- **导出销售数据时按周分组**，脚本自动从表头数出周数，不用给 `--weeks`。
- `--products` 必填，且**必须含 `External ID`**（回写用的唯一映射码）。
- **产品主数据导出的筛选条件只勾 `can be sold`**——加别的条件会漏货（2026-08-02 实测 `VO active=true` 只有 4575 行，漏掉 9 个在管 SKU）。
- `--test-sku`：首次导入试水，先出单条回写表核对，**同时照常出全量表**，验完直接导全量。

# 八、采购数量与频次（指定供应商）

📖 详见 [../po_frequency/README.md](../po_frequency/README.md)（必需列清单、导出筛选建议、口径三条规则）。

把某供应商的 `purchase.order` 导出整理成「采购了哪些产品、各买几次、每次多少」的表。**纯整理不下结论**（与会议延伸出的分析无关）。纯 CLI，无双击入口、无 GUI。

```bash
python3 po_frequency/po_frequency.py <purchase.order.xlsx> [--vendor NAME] [--out PATH]
```

- 输入：`purchase.order` **行式导出**（Order Lines 粒度，订单头空行脚本自动 ffill）。
- `--vendor`：按供应商名过滤（子串、忽略大小写）；导出已单供应商时可省略。
- 产出：`output/<Vendor>_Purchase_Quantity_and_Frequency.xlsx`，两 sheet **英文表头**——`Summary`（每产品：频次/总量/每次均最大最小/首末采购/跨度/平均间隔，按频次降序）+ `Details`（逐笔：日期/单号/产品/编码/数量/单价）。
- 口径：订单头 ffill；SKU 归一（去 `x2/*2/_VO`）；频次 = 不同 `Order Reference` 去重。

# 注意事项

- **真实数据**放 `raw_data/`，测试/参考数据放 `test-data/`，输出在 `output/`——均已 gitignore，不进版本库、不进 iCloud。
- 无货勾选：在 Excel 里把无货行的「无货(1=缺货)」列填 `1`（0 = 正常）。多品订单缺某件只标那一行。**全 0 才整单发货，任一留空会报警**（防漏返回默认全发）。
- `账单MMDD` 标签统一英文数字；脚本会自动剥离旧标签再贴当日标签。
- 输出同名文件自动加序号，不覆盖既有产出。
- 页边距单位为英寸（0.9 / 0.8）。
- **「先核对再发货」**：原「与昨日发货表 VO Tracking No 去重」的方案已**否决**，改用发货集合反查完整天猫真实状态的护栏——覆盖面更大（见根 README 进度节）。
- `vo_orders/jd_export.py`（京东选列导出）**已下架，代码保留**：GUI 标签页已移除，当前无调用方。
